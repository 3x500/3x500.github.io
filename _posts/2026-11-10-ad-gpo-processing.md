GPO를 만들었다고 정책이 모든 PC에 적용되지는 않는다. 설정 내용과 적용 대상을 따로 확인해야 한다. GPO는 규정집, 링크는 어느 구역에 그 규정을 적용할지 정하는 연결로 생각하면 쉽다.

GPO는 Site·Domain·OU에 연결할 수 있다. 보안 그룹은 GPO를 직접 연결하는 컨테이너가 아니라 적용 대상 필터링 등에 사용한다. [Microsoft GPO 범위](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/group-policy/group-policy-scope)

## 기본 처리 순서

```text
Local → Site → Domain → 상위 OU → 하위 OU
```

일반적인 설정 충돌에서는 뒤에서 처리되는 정책이 앞선 값을 덮어쓸 수 있다. 같은 컨테이너의 여러 링크에는 링크 순서도 영향을 준다. 하지만 “가장 아래 OU가 언제나 이긴다”로 외우면 강제 적용 같은 예외를 놓친다. [Microsoft GPO 처리 방식](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/group-policy/group-policy-processing)

같은 컨테이너에서는 링크 순서 1이 가장 높은 우선순위를 가진다. 상속 차단은 상위의 일반 링크에서 내려오는 정책을 차단하지만, 강제 적용된 상위 링크까지 차단하지는 않는다. 강제 적용된 상위 링크의 충돌 설정은 하위 설정으로 덮어쓸 수 없다. 강제 적용이 보안·WMI 필터나 필요한 권한을 무시한다는 뜻은 아니다.

## 적용 여부를 바꾸는 조건

| 조건 | 확인할 내용 |
|---|---|
| 링크 위치·활성 상태 | 대상 객체의 경로에 적용되는 링크인가? |
| 사용자·컴퓨터 설정 | 바꾸려는 항목이 어느 쪽 설정인가? |
| 보안 필터링 | 필요한 읽기·적용 권한이 있는가? |
| WMI 필터 | 장비가 필터 조건을 충족하는가? |
| 상속 차단·강제 적용 | 기본 처리 순서에 예외가 있는가? |

사용자 설정은 사용자 객체, 컴퓨터 설정은 컴퓨터 객체의 위치가 기본 기준이다. 루프백 처리를 사용하면 사용자 정책 적용이 달라질 수 있으므로 사용 목적과 범위를 별도로 기록한다.

## 원본 정책 매트릭스를 목적·대상·검증으로 연결한다

| 정책 목적 | 연결·대상 예제 | 확인할 결과와 조건 |
|---|---|---|
| 도메인 계정 암호·잠금 | Domain 수준 정책 | 실제 도메인 정책과 대상 사용자 예외 정책(FGPP)을 구분 |
| DC 하드닝 | Domain Controllers OU | LDAP·감사·관리 접근의 호환성과 실제 DC 결과 |
| 서버 Baseline | Servers OU의 파일럿·승인 범위 | 서버 역할별 방화벽·서비스·관리 도구 영향 |
| 단말 Baseline | Workstations OU | 사용자 업무·보안 설정·예외 장비 영향 |
| 관리자 로그온 제한 | 계정·장비와 로그온 유형에 맞는 범위 | 관리 경로와 긴급 복구 접근까지 테스트 |

원본의 암호 길이·로그 크기·검토 주기는 조직의 설계안이다. 수치를 적용했다는 사실만으로 특정 규정 준수를 완료했다고 쓰지 않는다. 계정 정책과 FGPP, 로그 보존 요구·수집량, OS 지원 조건을 별도 검토한다.

도메인 사용자 암호 정책은 일반적인 사용자 OU GPO로 사용자마다 나눠 적용하는 방식으로 설명하지 않는다. FGPP는 사용자와 Global 보안 그룹을 대상으로 하며 OU에 직접 적용하는 정책이 아니다. [세분화된 암호 정책](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/get-started/adac/fine-grained-password-policies)

## 충돌 예제를 처리 순서와 분리해 검증한다

설명용으로 상위 OU와 하위 OU가 같은 설정을 다르게 구성했다고 가정한다. 일반 링크라면 하위 OU의 설정이 최종값이 될 수 있다. 상위 링크를 Enforced로 바꾸면 충돌 항목의 결과가 달라질 수 있지만 대상의 읽기·적용 권한과 WMI 필터까지 무시하는 것은 아니다. GPO 전체가 승리했다는 말 대신 **항목별 최종값과 적용 이유**를 남긴다.

사용자 루프백 Merge/Replace는 공유 단말 등의 사용자 환경을 컴퓨터 위치에 맞춰 제어할 때 검토한다. 일반 사용자 OU의 처리와 다른 효과가 있으므로 파일럿 계정·장비 조합으로 시험하고 적용 범위를 기록한다. [GPO 필터·루프백·상속 범위](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/group-policy/group-policy-scope)

## 파일럿에서 원복까지 같은 검사표를 사용한다

원본 보안 문서의 파일럿→검증→전체 배포→모니터링을 변경 통제로 구체화한다. Default Domain Controllers Policy 등 DC 정책의 실제 링크 위치도 GPMC에서 확인하며 도메인 루트에 무조건 연결하지 않는다.

| 단계 | 남길 자료 | 다음 단계 조건 |
|---|---|---|
| 변경 전 | GPO 백업·설정 보고서·GUID·링크·순서·필터·권한 | 목적·영향·원복 책임자 승인 |
| 파일럿 | 대표 OS·역할·사용자와 비대상 장비 | 필요한 설정 적용과 제외 범위 확인 |
| 검증 | gpresult·클라이언트 로그·실제 설정·업무 | 오류·관리 접근·호환성 영향 해소 |
| 확대 | 배포 범위·시각·중단 임계 | 단계별 업무 확인과 관찰 기간 충족 |
| 원복·인수 | 변경 설정·링크와 실제 결과의 복원 | 새로고침·로그오프·재시작 필요 여부까지 확인 |

GPO 백업만으로 링크·범위·모든 외부 의존성이 복원된다고 가정하지 않는다. 정책을 해제해도 설정 종류에 따라 값이 남을 수 있으므로 실제 설정 복구까지 검증한다. 오류 발생 시 Enforced·상속 차단을 추가하며 덮기보다 이번 변경을 식별해 되돌린다.

## 예외 정책의 범위를 작게 잡는다

공용 PC에서 사용자 환경을 제한하려는 정책과 서버 보안 정책을 하나의 GPO에 섞으면 영향 추적이 어려워진다. 대상과 변경 이유를 기준으로 나누되, 설정 하나마다 GPO를 만드는 식의 과도한 분리도 피한다. [Microsoft GPO 개요](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/group-policy/group-policy-overview)

새 GPO는 파일럿 OU에서 대상 장비로 확인한다. 설정값뿐 아니라 적용 대상과 제외 대상이 의도대로 구분되는지 봐야 한다. 암호 정책처럼 도메인 계정에 대한 별도 적용 규칙이 있는 항목은 일반 OU 설정과 동일하게 설명하지 않는다.

변경 기록에는 GPO 이름, 링크 위치, 필터, 변경한 설정, 기대 동작, 원복 방법을 남긴다. 적용 결과 확인은 다음 글에서 다룬다.
