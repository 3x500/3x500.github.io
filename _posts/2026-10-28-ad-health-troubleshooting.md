사용자가 “AD가 안 된다”고 말할 때 실제 증상은 로그인 실패, 가입 실패, 파일 접근 거부, 정책 미적용 등으로 다르다. 모든 항목을 한 번에 수정하기보다 실패 범위를 먼저 좁힌다.

어느 사용자·장비·지점에서 언제부터 어떤 작업이 실패하는지 확인한다. 전체 장애인지 일부 대상의 문제인지에 따라 먼저 볼 항목이 달라진다.

## 증상에서 출발한다

| 증상 | 우선 확인할 것 |
|---|---|
| 도메인 가입 실패 | DNS·DC 검색, 통신, 가입 권한, NetSetup 로그 |
| 인증 실패 | 계정 상태, DNS·시간, 접속 DC와 인증 로그 |
| 파일 접근 거부 | 인증 성공 여부, 그룹·세션·공유·파일 권한 |
| GPO 미적용 | 대상 OU·링크·필터, gpresult, SYSVOL·복제 |
| DC별 결과 불일치 | 같은 객체의 조회 대상과 복제 상태 |

이는 출발점이지 모든 원인을 판정하는 표는 아니다. 특히 복제 장애는 DNS·네트워크·인증 등 여러 원인으로 발생할 수 있다. [Microsoft 복제 진단](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/troubleshoot/troubleshooting-active-directory-replication-problems)

## DC 기본 진단 예제

DC의 관리자 권한 명령 프롬프트에서 실행할 예제다. 원격·전체 범위 조회는 별도 권한과 통신 조건을 확인한다.

```text
dcdiag /test:Advertising /test:Services /v
dcdiag /test:DNS /DnsBasic /v
repadmin /replsummary
```

여기서는 DNS 기본 진단을 명시했다. `dcdiag`의 다른 DNS 검사에는 동적 업데이트 테스트처럼 테스트 레코드를 등록·삭제하는 동작도 있으므로 모든 옵션을 순수 조회로 취급하지 않는다. 출력은 실제로 수집하지 않았다. [Microsoft DCDiag 옵션](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/dcdiag)

## 시간 상태는 값과 원본을 함께 본다

문제가 있는 장비에서 로컬 관리자 권한으로 조회한다.

```text
w32tm /query /status
w32tm /query /source
```

동기화 원본과 마지막 동기화 등 상태를 확인한다. 현재 시각이 비슷해 보여도 원본이 의도한 계층과 다르면 이후 문제가 반복될 수 있다. 이 조회만으로 상대 장비와의 실제 오차까지 측정했다고 보지는 않는다. [Microsoft Windows Time 도구](https://learn.microsoft.com/en-us/windows-server/networking/windows-time-service/windows-time-service-tools-and-settings)

## 원본 점검표를 주기·증거·담당자로 바꾼다

원본 구축·DNS 문서의 일일·주간·월간 점검은 다음처럼 운영 결과를 남기는 표로 관리한다. 주기는 설명용 운영안이며 Microsoft 공통 필수 주기가 아니다. 장애 영향·변경량·복구 목표에 맞춰 조정한다.

| 주기 예제 | 대상·도구 | 관찰과 판정 | 책임·조치 |
|---|---|---|---|
| 일일·변경 직후 | DC 서비스·dcdiag·복제 | 검사 범위·실패·최근 성공·오류 변화 | AD 운영자: 새 실패 원인 분류·티켓 연결 |
| 일일 | 내부 DNS·대표 SRV/A·전달 이름 | DNS별 응답·권한 데이터·지연·실패 구분 | DNS 운영자: 영역·등록·전달·통신 분기 |
| 일일 | 시간·보안 수집·백업 작업 | 원본·동기 상태·수집 지연·작업 결과 | 담당자: 공백·실패와 업무 영향 확인 |
| 주간 | Site/Subnet·디스크·로그·이벤트 추세 | 신규 대역·여유량·반복 실패·보관 여유 | 네트워크/AD 담당: 누락과 임계 검토 |
| 월간·이동 시 | 고권한 그룹·위임·계정 수명주기 | 승인·예외 만료·직접/중첩 권한 | 계정/리소스 오너: 회수·재승인 |
| 계획된 주기 | 복구 훈련·백업 접근·인증서 | 유효 복구 지점·만료·격리 복원 결과 | 복구 책임자: 보관·갱신·훈련 개선 |

각 행에 실제 대상·실행 위치·실행 계정·시각·정상 기준·증거 위치·미확인 이유를 덧붙인다. 명령이 실행됐다는 기록과 정상 판정은 구분한다. 수집하지 않은 DC·지점은 정상 수에 포함하지 않는다.

## 경보 임계와 프로토콜 한계를 섞지 않는다

| 원본의 기준 예제 | 운영에 적용할 방식 |
|---|---|
| 복제 지연 24시간 | 별도 경보 임계. 실제 수명·스케줄·마지막 성공과 구분 |
| 시간 오차 2분 | 조기 경보 예제. Kerberos 적용 허용값·시간 원본은 별도 확인 |
| 인증서 갱신 30일 전 | 갱신 소요·승인·배포 시간을 고려한 선행 작업 시점 |
| 로그 크기·디스크 여유 | 수집량·보관 요구·증가율과 경보 대응 시간으로 산정 |

시간을 조정하기 전에 DC·호스트·클라이언트의 원본과 역할을 확인한다. 원본 시나리오의 오류 문구 하나를 시간 이탈의 확정 원인으로 사용하지 않는다. 가상 DC의 시간 동기화 역시 하이퍼바이저·OS·PDC 역할 조건을 확인하고 일괄 비활성화 규칙으로 일반화하지 않는다.

## 원본 DNS 결과를 전체 PASS로 소개하지 않는다

진단 결과에는 실패·경고와 PASS가 함께 있을 수 있다. 일부 `passed test DNS` 문장을 전체 정상 증적으로 사용하지 않는다. 화면에 여러 포트의 명령·출력이 있으면 한 번의 실행 결과인지도 확인한다. 검사는 대상·옵션·시각·항목별 결과와 전체 요약을 함께 읽는다.

DNS 레코드 CSV나 영역 내보내기는 목록 비교·진단 자료다. ACL·AD 데이터·서버 전체를 복원할 백업을 대신하지 않는다. 수집 자료와 복구 자료를 저장·검증 항목에서 구분한다. [영역 내보내기의 진단 범위](https://learn.microsoft.com/en-us/powershell/module/dnsserver/export-dnsserverzone?view=windowsserver2025-ps)

## 정상 기준을 기록한다

실패 수, 최근 성공 시각, 조회한 DC, 기대한 응답을 남겨 전날·정상 장비와 비교한다. 이벤트 로그의 오류 한 줄만 지우는 방식보다 범위와 변화 추적이 중요하다.

서비스 재시작·강제 복제·계정 재설정은 상태를 바꾸는 조치다. 원인과 영향, 확인할 결과를 정한 뒤 수행하고, 정상 여부는 사용자 업무 동작까지 확인한다. 공개 글에는 원본 로그 대신 진단 순서와 판단 근거를 정리한다.

이번 변경 이후 실패가 생기면 신규 변경을 중단하고 이전 설정·관찰과 비교한다. 설정 복원 후 같은 사용자·장비·지점·업무에서 확인하고 남은 오류·제외 범위를 기록한다. 한 진단 도구의 정상값으로 다른 기능의 검증을 닫지 않는다.
